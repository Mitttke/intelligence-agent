Apollo Lead Gen Pipeline

N8NCLAUDE AIAPOLLOHUBSPOT

Hiring signal detection and cross-border expansion targeting

An agentic workflow that spots companies hiring outside their home country, a strong signal they need help employing people across borders. It partitions Apollo searches by HQ country, keeps only cross-border job postings, dedupes against HubSpot and a 90-day cooldown ledger, and delivers enriched leads with AI-drafted outreach to sales leaders every Monday.

  • Partitioned search guarantees every result is hiring outside its HQ country, so domestic hiring never produces a false positive
  • Four dedupe layers: company name before enrichment, domain after enrichment, email at contact level, plus a 90-day cooldown ledger on SharePoint
  • Claude drafts each outreach email under a strict style contract, then a code-side scrub catches AI-sounding phrasing and flags the draft with a [CHECK] tag instead of hiding it
  • HubSpot stays read-only and nothing reaches a prospect automatically. Sales leaders get a review digest and decide every outreach

ICP Market Movements

N8NCLAUDE AISHAREPOINTHUBSPOT

Competitive intelligence and trigger event routing

A continuous intelligence engine that reads 44 sources every week for trigger events like funding rounds, M&A, international expansion and leadership changes, then matches them against the 19 ICP rows owned by the CRO and marketing. Events are verified against Apollo enrichment, checked against HubSpot for existing relationships and warm intro paths, and delivered as regional digests with Word attachments.

  • 44 fetches per run: 23 publisher RSS seeds plus 21 Google News queries with regional locales, all fail-soft so one dead feed never kills the run
  • Code filters noise before any LLM call, and the JSON contract is validated in code after it. No source URL means the event never exists
  • Apollo enrichment is the authority on headcount and HQ. A second code pass re-checks the ICP match with size tolerance bands and jurisdiction aliasing
  • A SharePoint ledger tracks every surfaced event with a 60-day cooldown and fails closed on read errors, so duplicates can never reach sales
  • HubSpot metadata-only reads produce the line reps actually use: who owns the account, when you last spoke, and who can make the intro

// APPROACH & TRADE-OFFS

Sole builder on both systems. I scoped the ICP rules with the CRO and marketing, agreed the security boundaries with our security director, and owned everything else end to end. Both workflows shipped inside 23 working days, including a few lost to waiting on API keys.

01

Build vs buy

I built custom agentic workflows instead of buying an intent-data platform. The vendors sell generic signals and charge per seat. None of them understood an ICP defined by cross-border movement, and none of them could join a signal to our own CRM context.

02

LLM vs code

Deterministic code handles about 90 percent of the pipeline: noise filtering, dedupe, date windows, size-band math. That keeps token cost down and hallucinations out. The model gets one narrow job, semantic matching and summarisation, and code validates everything it returns.

03

Trust vs automation

The CRM stays read-only and nothing reaches a prospect without a human rewrite. Digests and tracking workbooks built trust with sales leaders first. Automated CRM writes come later, earned by conversion data, not assumed on day one.
